1. Pemodelan Alur Kerja Klinis Master (BPMN Swimlane)

Alur pelayanan rawat jalan dirancang terpadu dalam 6 jalur aktor yang saling terkoordinasi secara asinkronus dan real-time:

👤 1. Pasien / Keluarga
Tiba di Faskes → Menyerahkan KTP (NIK) di Loket → Memberikan Persetujuan (Consent UU PDP) → Menerima Karcis Antrean & Kartu Berobat → Menunggu di Ruang Tunggu Poli → Masuk Ruang Periksa saat Dipanggil → Menerima Edukasi & Lembar E-Resep / Resume Medis.
🖥️ 2. Petugas Pendaftaran
Input NIK 16 digit → Query Validasi IHS SATUSEHAT → Verifikasi/Input Demografi → Perekaman Informed Consent (Opt-In/Out) → Pilih Poli Tujuan & Triase → Terbitkan Tiket Antrean (misal: A-01) & Cetak Kartu Pasien Barcode.
👩‍⚕️ 3. Perawat Poliklinik
Monitoring Worklist Poli → Tekan Tombol "Panggil Pasien" (Trigger TTS Audio & TV Display) → Anamnesis Awal & Pengukuran TTV (Tensi, Nadi, Suhu, SpO2, BB/TB) → Evaluasi Early Warning Alert IMT & TTV → Ubah Status Kunjungan: in-progress.
👨‍⚕️ 4. Dokter DPJP
Buka Dashboard 1 Layar → Anamnesis SOAP Terpadu → Input Diagnosis Primer/Sekunder (ICD-10) → Input Tindakan Medis (ICD-9-CM) → Order Penunjang Lab (LOINC) / Rad (jika perlu) → E-Prescribing KFA (dengan visualisasi jadwal minum & cek alergi) → Rencana Kontrol & Kepulangan → Finalisasi Berkas.
💊 5. Penunjang & Farmasi
Laboratorium: Input Hasil Uji + Nilai Rujukan + Flag Kritis.
Radiologi: Input Ekspertise Pembacaan X-Ray/USG.
Apoteker: Verifikasi E-Resep KFA & Jadwal Minum Obat → Cetak Etiket & Dispensing Obat.
⚙️ 6. Background Engine
Otomatis mentransformasikan data lokal → Resource FHIR HL7 R4 (Encounter, Condition, Observation, MedicationRequest, Composition) → POST ke SATUSEHAT Gateway → Auto-Lock berkas dalam 24 jam & Log Audit Addendum.

2. Diagram Transmisi Data Teknis (Sequence Diagram)

ALUR INTERAKSI TEKNIS: DPJP → DATABASE LOKAL → SATUSEHAT CLOUD

[DPJP UI] --(1) Submit Form SOAP / Resep KFA--> [Next.js API Handler: /api/encounters]
[Next.js API] --(2) Write SQLite Local Database (Drizzle ORM)--> [Local DB Store]
[Local DB Store] --(3) Data Committed (HTTP 200 OK)--> [Next.js API]
[Next.js API] --(4) Background Async FHIR Transformation Engine--> [FHIR Bundle Payload]
[Next.js API] --(5) HTTPS OAuth2 POST /Encounter, /Condition, /MedReq--> [SATUSEHAT Cloud Gateway]
alt Jika Gateway Respons 201 Created
  [SATUSEHAT Cloud] --> [Next.js API]: Return FHIR Resource ID (e.g. "ss-enc-89210")
  [Next.js API] --> [Local DB]: Update encounters.syncStatus = 'synced'
else Jika Gateway Timeout / Error 504
  [SATUSEHAT Cloud] --> [Next.js API]: Error 504 / Connection Timeout
  [Next.js API] --> [Local DB]: Write satusehat_sync_logs (status: 'failed', retry_count: 0)
  [Next.js API] --> [DPJP UI]: Banner Notifikasi "Data tersimpan lokal, antrean sync pending"
end

3. Spesifikasi Fungsional Terinci (FSD per Fase Pelayanan)

FASE-01 Pendaftaran Pasien, Validasi NIK/IHS & Informed Consent UU PDP Loket / Admission
Antarmuka & Komponen PatientRegistrationModule.tsx, QueueTicketPrintModal.tsx, PatientCardPrintModal.tsx
Input & Parameter NIK (16 digit), Nama Lengkap, Tanggal Lahir (YYYY-MM-DD), Jenis Kelamin, No HP, Alamat, Golongan Darah, Kontak Darurat, Payer (BPJS/Mandiri), Persetujuan SATUSEHAT (Opt-In/Out).
Aturan Validasi (Rules)
  • NIK wajib 16 digit numerik dengan kode wilayah provinsi yang valid (11-96).
  • Sistem mengecek keunikan NIK; jika duplikat, tampilkan profil pasien eksisting.
  • Pilihan Consent "Opt-In" membuat status FHIR Consent aktif untuk pengiriman data cloud.
Aksi & Trigger Tombol [Cari NIK]: Query ke endpoint /api/satusehat/patient?nik=... untuk auto-fill data.
[Daftarkan Pasien & Cetak Antrean]: POST /api/patients & POST /api/queue.
Output Sistem Data pasien tersimpan di patients, item antrean dibuat di queue_items, pop-up cetak karcis antrean & kartu berobat pasien ber-barcode MRN.
FASE-02 Manajemen Antrean Poli, Pemanggilan Suara TTS & Public TV Display Triage / Poli
Antarmuka & Komponen ClinicalShiftBar.tsx, EhrLeftSidebar.tsx, PublicQueueDisplayModal.tsx, queueVoiceAnnouncer.ts
Input & Parameter Pilihan Poli (Poli Penyakit Dalam, Poli Jantung, Poli Anak, dll), Filter Status Antrean (Semua, Menunggu, Sedang Dilayani, Selesai).
Aturan Validasi (Rules)
  • Pasien dengan triase Geriatric atau Urgent diprioritaskan di daftar tunggu.
  • Hanya 1 pasien yang dapat berstatus in-progress per dokter/ruangan periksa.
Aksi & Trigger Tombol [Panggil Pasien]: Memanggil audio Text-to-Speech Web API: "Nomor Antrean [No], silakan menuju [Nama Poli], Ruang [No Ruang]", update status antrean ke in-progress, dan sinkronisasi tampilan monitor Public Queue Display.
Output Sistem Audio pengumuman terdengar di speaker ruang tunggu, nomor antrean terpampang di monitor TV publik, worklist DPJP otomatis memuat profil pasien aktif.
FASE-03 Pemeriksaan Fisik, Tanda-Tanda Vital (TTV) & Early Warning Score Perawat / DPJP
Antarmuka & Komponen VitalsCard.tsx, validation.ts (evaluateVitalSigns)
Input & Parameter Sistolik (mmHg), Diastolik (mmHg), Nadi (bpm), Suhu (°C), Pernapasan (x/mnt), SpO2 (%), Berat Badan (kg), Tinggi Badan (cm), Catatan Pemeriksaan Fisik.
Aturan Validasi (Rules)
  • Kalkulasi Indeks Massa Tubuh (IMT / BMI): BB (kg) / (TB (m))² secara real-time.
  • Early Warning Alerts: Sistolik > 180 / < 90 mmHg (Kritis), Nadi > 120 / < 50 bpm (Kritis), Suhu > 38.5°C (Demam Tinggi), SpO2 < 92% (Hipoksia).
Aksi & Trigger Tombol [Simpan TTV]: Memvalidasi rentang fisiologis dan memperbarui data TTV di tabel vitals.
Output Sistem Nilai IMT dan kategori gizi ditampilkan; badge status "Critical Alert" merah menyala pada banner atas pasien jika ada parameter vital yang abnormal.
FASE-04 Asuhan Medis DPJP (SOAP), Kodifikasi ICD-10 & Prosedur ICD-9-CM Dokter DPJP
Antarmuka & Komponen OutpatientEntryForm.tsx (Sub-modul Anamnesis & Diagnosis)
Input & Parameter Keluhan Utama (*Subjective*), Anamnesis Riwayat Penyakit, Diagnosis Primer (ICD-10), Diagnosis Sekunder (ICD-10), Tindakan Medis (ICD-9-CM), Instruksi Edukasi.
Aturan Validasi (Rules)
  • Wajib mengisi minimal 1 Diagnosis Primer berstandar ICD-10 resmi.
  • Form dilengkapi pencarian autocomplete kode diagnosis internasional dan nama ramah pasien.
Output Sistem Tersimpan di tabel diagnoses dan procedures; siap dikirim sebagai FHIR Condition dan Procedure.
FASE-05 Penunjang Diagnostik (Laboratorium LOINC & Radiologi Modalitas) Penunjang Medis
Antarmuka & Komponen DiagnosticSupportModule.tsx, tabel diagnostic_orders, lab_results, radiology_results
Input & Parameter Kode Tes (LOINC), Kategori (Lab / Radiologi), Prioritas (Rutin, Cito/Urgent), Nilai Hasil Uji, Satuan, Rentang Rujukan Normal, Kesimpulan Ekspertise Radiologi.
Aturan Validasi (Rules) Sistem otomatis membandingkan nilai hasil lab dengan rentang rujukan: jika nilai melebihi batas, berikan flag visual "High", "Low", atau "Critical".
Output Sistem Hasil penunjang tampil di tab "Penunjang Lab & Radiologi" dan langsung terangkum dalam Resume Medis Terpadu.
FASE-06 Resep Elektronik (CPOE / E-Prescribing) Standar Master KFA Kemenkes DPJP & Farmasi
Antarmuka & Komponen OutpatientEntryForm.tsx, MedicationScheduleCard.tsx, PrescriptionPrintModal.tsx
Input & Parameter Kode Obat KFA Kemenkes (contoh: 93000182), Nama Obat, Sediaan, Dosis, Frekuensi, Waktu Minum (Sebelum/Sesudah Makan), Checkbox Jadwal (Pagi/Siang/Sore/Malam), Jumlah & Durasi (Hari).
Aturan Validasi (Rules) Deteksi Alergi Obat Otomatis: Jika obat yang dipilih memiliki relasi silang dengan daftar alergi pasien, tampilkan modal peringatan bahaya (*Clinical Decision Support*).
Output Sistem Tersimpan di tabel prescriptions, visualisasi kartu jadwal obat terbit, modal cetak lembar resep digital resmi ber-barcode siap diproses apotek.
FASE-07 Resume Medis Terintegrasi 1 Layar & Cetak Berkas Rekam Medis Clinical Review
Antarmuka & Komponen ResumeMedisPrintModal.tsx, EhrRightPanel.tsx, OutpatientTimeline.tsx
Input & Parameter Instruksi Tindak Lanjut, Tanggal Kontrol Ulang, Rujukan RS Lain (jika ada), Disposisi Kepulangan (Pulang Berobat Jalan, Rujuk Rawat Inap, Rujuk RS Luar).
Output Sistem Lembar Resume Medis Rawat Jalan resmi ber-kop rumah sakit, barcode nomor rekam medis, QR code keabsahan digital, dan rincian lengkap SOAP siap cetak (A4).
FASE-08 Penguncian Berkas 24 Jam (Permenkes 24/2022) & Audit Trail Addendum Legal Compliance
Antarmuka & Komponen MedicalRecordLockModal.tsx, tabel medical_addendums, field encounters.isLocked
Aturan Validasi (Rules)
  • Sesuai Permenkes No. 24/2022 Pasal 21, seluruh berkas rekam medis terkunci permanen setelah 24 jam pasca-pemeriksaan atau saat dokter menekan "Kunci Berkas".
  • Berkas terkunci tidak dapat diedit atau dihapus secara langsung (*Immutability Rule*).
  • Koreksi atau catatan tambahan hanya boleh dilakukan melalui formulir Addendum Medis yang merekam nama dokter dan timestamp ISO audit.
Output Sistem Ikon gembok merah aktif pada header, form beralih ke mode *read-only*, riwayat Addendum Medis terlampir permanen di bawah rekam medis asli.
FASE-09 Interoperabilitas FHIR R4, Inspector Payload & Failover Retry Sync Integration Engine
Antarmuka & Komponen SatusehatFhirDetailModal.tsx, RequestLogs.tsx, fhir-transformer.ts, /api/satusehat/sync-retry
Fitur Fungsional 1. Inspector JSON payload mentah untuk setiap resource FHIR (Encounter, Condition, Obs, MedReq, Consent, CarePlan).
2. Pelacakan status HTTP response code dan pesan error dari gateway Kemenkes.
3. Tombol [Retry Sync] untuk mengirim ulang resource yang mengalami kegagalan koneksi.
Persetujuan & Otorisasi FSD:
Spesifikasi Fungsional dan BPMN Alur Klinis ini merupakan dokumen acuan baku untuk pengembangan antarmuka, pembuatan tes QA, serta pelatihan operasional bagi tenaga medis di faskes.
