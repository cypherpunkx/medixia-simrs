1. Ringkasan Eksekutif & Matriks Pengguna

Sistem ini dirancang untuk mendigitalkan seluruh siklus pelayanan rawat jalan di fasilitas pelayanan kesehatan (Rumah Sakit dan Klinik) sekaligus memenuhi kewajiban bridging data rekam medis elektronik nasional sesuai amanat Permenkes No. 24 Tahun 2022.

Pilar Utama Arsitektur:
  • Single-Pane Clinical View: DPJP dapat melihat riwayat SOAP, TTV, hasil lab/radiologi, dan e-resep dalam satu layar tanpa reload.
  • Zero Data Loss & Resiliency: Penyimpanan lokal berkecepatan tinggi dengan Drizzle ORM + SQLite yang memiliki queue worker untuk sinkronisasi SATUSEHAT.
  • Informed Consent UU PDP: Manajemen persetujuan pasien aktif (Opt-In / Opt-Out) sebelum data dipertukarkan ke cloud.
  • Medical Record Lock 24 Jam: Integritas hukum rekam medis dengan sistem penguncian permanen dan pencatatan Addendum ber-audit trail.

2. Standar Tata Kelola Rekayasa (DoR & DoD)

Definition of Ready (DoR)

Syarat Story masuk ke Sprint Backlog:

  • Format User Story memiliki Acceptance Criteria Given-When-Then.
  • Kesesuaian Permenkes 24/2022 & standar Kemenkes terverifikasi.
  • Kodifikasi medis (ICD-10, ICD-9-CM, LOINC, KFA) telah dispesifikasikan.
  • Skema Drizzle dan endpoint API Next.js telah dipetakan.
  • State UI (loading, empty, error) sudah disepakati bersama.
  • Story Points telah disetujui tim Engineering.

Definition of Done (DoD)

Syarat Story dinyatakan selesai:

  • Lolos typecheck TypeScript (tsc --noEmit) tanpa error.
  • Unit & Repository tests mencapai code coverage ≥ 80%.
  • Payload FHIR JSON lolos validasi skema HL7 FHIR R4 resmi.
  • Kerahasiaan data terjaga: tidak ada Client Secret terekspos.
  • Format cetak (Resume, Karcis, Resep) rapi & proporsional.
  • Koreksi data rekam medis terkunci wajib melalui Addendum.

4. Rincian Lengkap User Stories & Kriteria Penerimaan

EPIC 01: Autentikasi, Manajemen Kredensial & Bridging SATUSEHAT (OAuth 2.0)

US-01.1 Koneksi OAuth 2.0 ke Gateway Auth SATUSEHAT Kemenkes RI Must Have

Sebagai: Administrator IT Faskes

Saya ingin: Menginput Client ID, Client Secret, dan memilih Environment (Staging / Production) untuk memperoleh JWT Access Token resmi,

Sehingga: Seluruh transaksi bridging rekam medis faskes memiliki izin akses aman dan terotorisasi oleh Kemenkes RI.

GIVEN Kredensial Client ID dan Client Secret yang sah dari DTO Kemenkes
WHEN Admin menekan tombol "Hubungkan ke SATUSEHAT"
THEN Sistem menerima token bearer aktif (TTL 3600 detik) dan menyimpannya secara terenkripsi.
US-01.2 Verifikasi & Profiling Identitas Faskes (Organization Resource) Must Have

Sebagai: Administrator IT Faskes

Saya ingin: Memverifikasi Organization ID faskes ke endpoint FHIR Organization/{id},

Sehingga: Memastikan faskes terdaftar secara valid di master database Kemenkes sebelum sinkronisasi dimulai.

GIVEN Token OAuth aktif dan Organization ID (contoh: 10000004)
WHEN Tombol "Verifikasi Faskes" dieksekusi
THEN Menampilkan nama resmi faskes, jenis pelayanan, status aktif, dan alamat faskes dari server SATUSEHAT.

EPIC 02: Pendaftaran, Identitas Pasien (NIK/IHS) & Manajemen Informed Consent (UU PDP)

US-02.1 Pencarian & Registrasi Pasien Berbasis NIK 16 Digit & Integrasi IHS Number Must Have

Sebagai: Petugas Pendaftaran (Loket)

Saya ingin: Mencari data pasien via 16 digit NIK yang langsung mengaitkan SATUSEHAT Patient ID (IHS),

Sehingga: Pasien tidak memiliki rekam medis ganda dan riwayat kesehatannya tersinkron secara nasional.

GIVEN Input 16 digit angka NIK KTP yang valid
WHEN Petugas melakukan pencarian / submit registrasi
THEN Sistem menautkan profil lokal dengan IHS Kemenkes (P-xxxxxxxxxx) dan mengisi data demografi secara akurat.
US-02.2 Manajemen Informed Consent Pertukaran Data Medis (UU PDP No. 27/2022) Must Have

Sebagai: Petugas Loket & Pasien

Saya ingin: Menetapkan status persetujuan (Opt-In / Opt-Out) berbagi data medis ke platform SATUSEHAT,

Sehingga: Hak privasi pasien terlindungi secara hukum dan faskes patuh pada regulasi perlindungan data pribadi.

GIVEN Pasien yang sedang mendaftar rawat jalan
WHEN Pilihan Consent diatur ke "Opt-In" atau "Opt-Out"
THEN Sistem menyusun payload FHIR Consent dengan provision type permit atau deny.
US-02.3 Penanganan Pasien Gawat Darurat Tanpa NIK (Emergency Fallback) Should Have

Sebagai: Petugas Pendaftaran IGD / Poliklinik

Saya ingin: Mendaftarkan pasien darurat tanpa NIK dengan Nomor Rekam Medis Sementara (Temporary MRN),

Sehingga: Pelayanan medis penyelamatan jiwa dapat segera dilakukan tanpa hambatan administrasi awal.

GIVEN Pasien darurat tanpa tanda pengenal
WHEN Petugas mencentang "Pasien Darurat Tanpa NIK"
THEN Sistem menerbitkan No RM sementara dan menunda sinkronisasi IHS ke status pending_identification.

EPIC 03: Antrean Poliklinik, Pemanggilan Suara Text-to-Speech & Display TV

US-03.1 Penerbitan Nomor Antrean Poliklinik & Triase Prioritas Must Have

Sebagai: Petugas Pendaftaran

Saya ingin: Menerbitkan tiket antrean dengan kode departemen dan triase (Reguler, Geriatri, Pediatri, Urgensi),

Sehingga: Pasien teralokasi secara berurutan pada poli yang dituju dengan estimasi waktu layanan yang jelas.

GIVEN Pasien dan poli spesialis tujuan yang dipilih
WHEN Pendaftaran poli dikonfirmasi
THEN Tiket antrean (misal: A-01) dibuat di tabel queue_items dan masuk worklist dokter hari ini.
US-03.2 Pemanggilan Pasien dengan Suara Text-to-Speech (TTS) & Public Queue TV Display Should Have

Sebagai: Perawat Poliklinik / Dokter DPJP

Saya ingin: Memanggil pasien dengan audio suara bahasa Indonesia dan menampilkan status di monitor ruang tunggu,

Sehingga: Pasien di ruang tunggu dapat mendengar dan melihat giliran periksanya secara jelas dan tertib.

GIVEN Antrean pasien berstatus "Menunggu" (Arrived)
WHEN Tombol "Panggil Pasien" ditekan oleh perawat/dokter
THEN Audio berbunyi: "Nomor Antrean A 0 1, silakan menuju Poli Penyakit Dalam"
AND Modal Public Queue Display memperbarui nomor aktif ke status "Sedang Dilayani".

EPIC 04 & 05: Asuhan Medis Rawat Jalan DPJP (SOAP), Kodifikasi ICD & Tanda Vital (TTV)

US-04.1 Dokumentasi Klinis SOAP, Anamnesis & Tindak Lanjut Pasien Must Have

Sebagai: Dokter DPJP

Saya ingin: Mengisi keluhan utama, riwayat penyakit (anamnesis), instruksi kontrol, dan status kepulangan,

Sehingga: Catatan asuhan medis terekam lengkap dan siap dikonversi menjadi FHIR Encounter dan CarePlan.

GIVEN Pasien dalam sesi konsultasi dokter aktif
WHEN Dokter mengisi form SOAP dan menyimpan rekam medis
THEN Data tersimpan ke tabel encounters dengan status kunjungan finished.
US-04.2 Kodifikasi Diagnosis ICD-10 & Prosedur Tindakan Medis ICD-9-CM Must Have

Sebagai: Dokter DPJP

Saya ingin: Memilih diagnosis primer/sekunder dari katalog ICD-10 dan tindakan medis dari katalog ICD-9-CM,

Sehingga: Diagnosis terstandarisasi untuk klaim pembiayaan dan interoperabilitas FHIR Condition & Procedure.

GIVEN Form entri diagnosis
WHEN Dokter mengetik kode "I10" atau "Hipertensi"
THEN Autocomplete menampilkan deskripsi medis resmi beserta nama ramah pasien dan mengaitkan ke encounter.
US-05.1 Pemeriksaan Fisik TTV, Kalkulasi IMT Otomatis & Early Warning Critical Badge Must Have

Sebagai: Perawat & DPJP

Saya ingin: Menginput Tensi, Nadi, Suhu, Pernapasan, SpO2, BB, TB dengan evaluasi otomatis,

Sehingga: Sistem menghitung IMT secara real-time dan memberikan peringatan visual jika TTV berada di rentang kritis.

GIVEN Pengisian BB (68 kg) dan TB (172 cm)
WHEN Data diinput pada modul Vitals
THEN IMT dihitung otomatis (22.99 kg/m² - Normal)
AND Jika tekanan darah > 180 mmHg, badge "Critical Alert" merah menyala pada banner profil pasien.

EPIC 06 & 07: Penunjang Diagnostik Lab/Rad & E-Prescribing Terstandar KFA

US-06.1 Order & Hasil Laboratorium Terstandar LOINC dengan Flag Nilai Kritis Should Have

Sebagai: DPJP & Petugas Lab

Saya ingin: Membuat permintaan lab serta memasukkan hasil tes darah dengan nilai rujukan,

Sehingga: Hasil tes terintegrasi di resume medis dan terpetakan ke FHIR DiagnosticReport.

GIVEN Permintaan uji laboratorium (misal: HbA1c atau Glukosa Sewaktu)
WHEN Analis lab menginput nilai hasil pemeriksaan
THEN Sistem menandai status "Normal", "High", atau "Critical" sesuai nilai rujukan klinis.
US-07.1 Resep Elektronik Berbasis Kamus Farmasi dan Alat Kesehatan (KFA) Kemenkes RI Must Have

Sebagai: Dokter DPJP

Saya ingin: Meresepkan obat menggunakan katalog master KFA resmi dengan bentuk sediaan dan aturan minum terstruktur,

Sehingga: Mengurangi resiko kesalahan obat (medication error) dan kompatibel dengan FHIR MedicationRequest.

GIVEN Modul E-Prescribing
WHEN Dokter memilih "Amlodipine 5 mg Tablet" (KFA 93000182)
THEN Bentuk sediaan, satuan, aturan minum (Sesudah Makan), dan checkbox jadwal minum (Pagi/Malam) tersimpan terstruktur.
US-07.3 Deteksi Interaksi & Peringatan Alergi Obat Otomatis (Clinical Decision Support) Should Have

Sebagai: Dokter DPJP

Saya ingin: Mendapatkan peringatan otomatis jika obat yang diresepkan memicu alergi pada pasien,

Sehingga: Mencegah insiden anafilaksis dan meningkatkan keselamatan pasien (patient safety).

GIVEN Pasien memiliki riwayat alergi tercatat "Penisilin"
WHEN Dokter mencoba menambahkan obat golongan Amoxicillin ke daftar resep
THEN Modal konfirmasi bahaya alergi muncul dan mewajibkan verifikasi klinis dokter sebelum melanjutkan.

EPIC 08, 09 & 10: Resume Medis, Kepatuhan Permenkes 24/2022 & Interoperabilitas FHIR

US-08.1 Dashboard Resume Medis Terintegrasi Satu Layar & Ekspor Cetak Berkas Resmi Must Have

Sebagai: DPJP & Pasien

Saya ingin: Meninjau seluruh ringkasan asuhan medis dalam 1 layar responsif dan mencetak lembar resmi berstandar RS,

Sehingga: Mempermudah koordinasi medis dan menyediakan dokumen legal bagi pasien.

GIVEN Kunjungan rawat jalan pasien yang telah selesai
WHEN Tombol "Cetak Resume Medis" atau "Cetak Resep" ditekan
THEN Modal cetak menampilkan dokumen format A4 ber-kop RS dengan QR code verifikasi dan barcode MRN yang siap cetak.
US-09.1 Penguncian Berkas Rekam Medis (Locking 24 Jam) Sesuai Permenkes No. 24/2022 Must Have

Sebagai: Komite Medis & Faskes

Saya ingin: Rekam medis terkunci permanen setelah 24 jam selesai pemeriksaan atau saat difinalisasi oleh dokter,

Sehingga: Mencegah manipulasi rekam medis secara ilegal demi kepatuhan hukum dan standar akreditasi.

GIVEN Berkas kunjungan yang telah melewati batas 24 jam atau difinalisasi dokter
WHEN Rekam medis berstatus terkunci (isLocked = true)
THEN Form input beralih menjadi mode hanya-baca (read-only) dengan penanda gembok status hukum aktif.
US-09.2 Pencatatan Addendum Medis dengan Jejak Audit Transparan (Audit Trail) Must Have

Sebagai: Dokter DPJP

Saya ingin: Menambahkan catatan perbaikan (Addendum) pada rekam medis yang telah terkunci tanpa mengubah data asli,

Sehingga: Penjelasan klinis tambahan memiliki histori audit yang sah (Nama Dokter, Timestamp, Catatan).

GIVEN Rekam medis yang berstatus terkunci permanen
WHEN Dokter mengisi formulir Addendum Medis
THEN Catatan tersimpan di tabel medical_addendums dan terlampir permanen di bawah riwayat kunjungan.
US-10.1 Inspector Payload FHIR R4 & Mekanisme Failover / Retry Sinkronisasi Must Have

Sebagai: Administrator IT Faskes

Saya ingin: Memeriksa status pengiriman resource FHIR per item dan melakukan retry manual jika gagal,

Sehingga: Gangguan jaringan tidak mengakibatkan data hilang dan seluruh data berhasil terkirim ke Kemenkes.

GIVEN Status sinkronisasi salah satu resource mengalami error (misal: HTTP 504 Gateway Timeout)
WHEN Admin membuka modal "Detail Sinkronisasi FHIR" dan menekan tombol "Retry Sync"
THEN Sistem mengirim ulang payload ke endpoint SATUSEHAT dan memperbarui status menjadi synced jika berhasil.

6. Matriks Mitigasi Risiko & Ketahanan Sistem (Resilience)

Potensi Skenario Kegagalan Dampak Klinis / Operasional Mekanisme Mitigasi Rekayasa Otomatis
Server SATUSEHAT Downtime / Timeout (HTTP 504) Pelayanan pasien terancam berhenti jika bergantung penuh pada cloud (online-only). Offline-First Architecture: Seluruh data disimpan langsung ke SQLite lokal faskes. Status sinkronisasi ditandai pending di satusehat_sync_logs, dan tombol Retry Sync disiapkan untuk pengiriman ulang saat jaringan pulih.
Token OAuth 2.0 Expired Saat DPJP Submit Form Pengiriman data rekam medis gagal dan dokter berpotensi kehilangan input. Transparent Auto-Refresh: Middleware mendeteksi status 401, mengambil token baru via OAuth refresh pipeline secara asynchronous di latar belakang, lalu mengirim ulang form tanpa meminta dokter mengetik ulang.
Duplikasi Pendaftaran NIK Pasien Tercatatnya dua Nomor Rekam Medis untuk satu orang yang sama. Unique Constraint Validation: Database menolak NIK duplikat dan UI otomatis mengarahkan ke profil pasien yang sudah terdaftar sebelumnya.
Upaya Pengubahan Data Medis Terkunci (> 24 Jam) Pelanggaran hukum terhadap Permenkes No. 24 Tahun 2022 Pasal 21. Immutability by Design: API menolak mutasi UPDATE/DELETE pada encounter berstatus locked. Setiap koreksi hanya dapat dicatat sebagai record baru di tabel medical_addendums.
